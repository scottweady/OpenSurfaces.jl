# Code map

Which functions of `src/` each feature of OpenSurfaces runs. On the left are the kernel families that `Evaluator`
sums (`Stokeslet3D`, `LaplaceKernel3D`, `LaplaceKernel2D` with its gradient, `BiharmonicGradient2D`, `MHKernel`, a
plain function, and line sources on a `BoundaryDisc`), and below them the options: sources and targets, fast sums,
operators, geometry, boundary quadrature, and building blocks used on their own. Each option is marked with the
kernels it applies to (S: Stokeslet3D, L: LaplaceKernel3D, 2: LaplaceKernel2D, B: BiharmonicGradient2D, M: MHKernel,
C: a function, Γ: line sources); every marked combination was checked by running it, and the underlined mark is the
kernel the option is compared with. Each setting is a small run, changed from the base case
(`Evaluator(Stokeslet3D(), ad)` on the unit disc at p = 8, 5632 area nodes, one apply) in that setting only, under
line coverage, and the lines it executes are mapped back to the top-level functions of `src/`. A function is a name
in a file, with all its methods there. The base case builds its mesh; the other settings start from the same mesh,
built once before the runs.

On the right is the package, by directory: `geometry` (panels, curves, meshes), `kernels` (point kernels, symbols,
fast sums), `quadrature` (local corrections) and `evaluators` (`Evaluator`, volume potentials, the single layer).
Click a directory to open it; each file has one dot per function. A link joins a setting to every visible row in
which it runs functions that the setting it is compared with does not (a kernel is compared with the base case, an
option with its underlined kernel); the wider the link, the more functions. Hover over a kernel to dim the options
that do not apply to it, over any setting to see the functions it runs, and over a dot to see the function's name,
its docstring and the settings that run it.


The map shows only what these runs reach: options not exercised here (targets on ``\Gamma`` for line sources, a
`Stokeslet3D` remainder summed directly, a symbol's gradient outputs) show up as not run. It is regenerated by hand
after a change to `src/`, so it may lag the code; the date and commit of the run are under the map. To regenerate it
(about three minutes; from the package root):

```
julia --project=docs docs/codemap.jl
```

## Layout

| Path | |
|:--|:--|
| `src/OpenSurfaces.jl` | the module docstring (the kernel contract), `DEFAULT_TOL`, includes, the FFTW threads fix in `__init__`, exports |
| `src/geometry/` | `panels.jl` (`Vec2`, panel rules, `CurvePanel`, `BoundaryDisc`, `AreaDisc`, drop and curve accessors), `boundary.jl` (`discretize_curve`, `discretize_curves`, `reverse_curve`, `local_feature_size`), `mesh.jl` (`build_mesh` by Gmsh, `film_drops`, `mesh_quality`), `interpolate.jl` (`interpolate_nodal`) |
| `src/kernels/` | `kernels.jl` (closed forms `G2`, `G3`, `P2`, `T2`, `stress2`; `StokesKernel`, `TractionKernel`), `laplace.jl` (2D Laplace and biharmonic kernels), `helmholtz.jl` (`MHKernel`, `MHNormalKernel`), `fmm.jl` (FMM2D and FMM3D Stokes wrappers, `interleave`), `symbol.jl` (`SymbolKernel`, `Stokeslet3D`, `LaplaceKernel3D`), `ewald.jl` (`EwaldStokes3D`, `SmoothConvolution`), `ewald2d.jl` (`FilmEwald`) |
| `src/quadrature/` | `line_quad.jl` (`LineQuad`, line corrections, the 2D Stokes single layer and traction on Γ), `area_quad.jl` (`area_correction`, `area_local_weights`, `AreaUpsampling`, graded edge layers) |
| `src/evaluators/` | `evaluator.jl` (`Evaluator`, its fast sums by kernel, `evaluator_matrix`, `local_blocks`, `panel_groups`, `mul!`), `volume.jl` (`VolumePotentials`), `single_layer.jl` (`SingleLayer3D`) |
| `test/` | `test_geometry.jl`, `test_kernels.jl`, `test_symbol.jl`, `test_quadrature.jl`, `test_evaluator.jl`, `test_volume.jl`, `test_single_layer.jl`; `common/` (shared references); `validation/` (convergence sweeps and timings, opt-in) |
| `examples/` | the scripts of [Examples](@ref): `single_layer_disc.jl`, `charged_disc.jl`, `rigid_disc.jl`, `ellipse_single_layer.jl`, `screened_kernel.jl`, `stokes2d_curve.jl`, `holes_and_drops.jl` |
| `docs/` | this site: `make.jl`, `src/` (the pages), `figures/` (data and plots), `codemap.jl`; `.github/workflows/Documentation.yml` builds it and publishes it to the gh-pages branch |
